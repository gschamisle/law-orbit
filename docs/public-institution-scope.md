# 공공기관 정의·적용범위 검토

공운법의 적용 대상을 다른 법령이 어떻게 차용하는지, 민영화법의 조건을 어디서 확인해야 하는지, 지정 변경 때 어떤 규정을 다시 읽어야 하는지 확인하는 기능입니다. 공공기관 메뉴의 **정의·적용범위 검토**에서 이용합니다. 원문을 열어도 현재 지도 기준은 유지합니다.

## 1. 정의·적용범위

- 공운법 제2·4·5·6조를 인용하는 근거와 **조 번호 없는 정의 차용**을 별도로 기록합니다.
- 지정기관 기준, 지정 요건 차용, 기관 유형 한정, 추가 조건, 제외·예외 문구를 구분해 검색합니다. 문구에 붙인 검토 표지이며, 특정 기관의 법적 적용 여부를 판정한 결과가 아닙니다.
- 간접 연결은 중간 조문 하나까지 추적하고 두 인용의 원문과 항·호·목을 보존합니다. 정의가 있는 조 번호가 같아도 서로 다른 호를 인용하면 연결하지 않습니다.
- 예: 정보공개법 제2조제3호다목 → 공운법 제2조제1항 → 제4·5·6조. 정보공개법이 전자정부법의 **정보통신망 정의**를 인용하는 부분은 기관 정의 경로로 연결하지 않습니다.
- 예: 공공데이터법 제2조제1호 → 지능정보화 기본법 제2조제16호가목 → 공운법. 마지막 인용에는 조 번호가 없으므로 제4조 직접 인용으로 바꾸지 않습니다.
- 원래 인용 그래프에 추론한 직접 인용선을 추가하지 않습니다. 경유 연결은 별도의 근거 목록입니다.

## 2. 민영화·특례

민영화법 제2·3·15·17·20·21조의 대상기업, 다른 법률과의 관계, 준용·특례, 적용배제 조건을 원문과 함께 제공합니다. 상법·한국가스공사법·인천국제공항공사법·한국공항공사법을 수집해 기존 인용 분석에 포함했습니다.

제21조의 지분 요건과 최초 주주총회 이후라는 조건을 그대로 보여 줍니다. 과거 기업명을 현재 기업명에 자동 대응하지 않으며 법률 우선순위·현재 적용 여부를 자동 판정하지 않습니다. 조 번호 없는 법령 참조는 전체 법령 읽기로 열립니다.

## 3. 지정 변경

정기 지정 발표 PDF를 내려받아 원문 표·기관명·전후 유형·쪽수·파일 해시를 대조했습니다.

| 발표 | 신규 | 유형 변경 | 합계 |
|---|---:|---:|---:|
| 2025년 | 4 | 3 | 7 |
| 2026년 | 11 | 2 | 13 |

- 연도·기관명을 검색하고 공식 발표와 원문 표를 확인합니다.
- 유형 변경에는 기관 유형을 한정한 규정을 우선 보여 주고, 전체 확인 후보도 열람할 수 있습니다.
- **발표일과 실제 효력 발생일을 구분합니다.** 확인하지 않은 실제 적용일은 비워 둡니다.
- 변경 발표 20건이며 전체 기관 명부, 연중 수시 변경, 모든 연도 자료는 아닙니다. 검색 결과 없음은 미지정이라는 뜻이 아닙니다.
- 2025년 변경에도 관련 법령은 현재 수집 판본으로 보여 줍니다. 과거 시점의 적용 판단은 지원하지 않습니다.
- 계약사무규칙 제3조처럼 지정 당시 회계연도와 기존 원인행위를 다르게 취급하는 경과 문구도 원문으로 확인해야 합니다.
- 자동으로 다음 연도의 발표를 추정하지 않습니다. 새 발표는 수집 프로필 추가와 표 검토가 필요합니다. PDF가 검토한 해시와 다르면 기존 등록부를 덮어쓰지 않고 실패합니다.

## 실제 수집·분석 결과 (2026-09-21)

기존 12문서에 **16문서**를 추가했습니다. 총 **28문서**, 조문 분석 **27문서·2,199조**, 직접 근거 **47건**(조문 인용 46 + 조 번호 없는 정의 차용 1), 경유 경로 **5건**입니다. 이 건수는 검토해야 하는 법령 수나 개정 의무의 수가 아닙니다.

추가 범위는 정보공개 법·령, 청탁금지법, 공공데이터법, 전자정부법, 지능정보화 기본법, 공공기록물 법·령, 판로지원 법·령, 안전활동 수준평가 고시, 소프트웨어 관리 규정, 상법, 3개 공사 설립법입니다. 법제처 API의 현행 목록과 본문 식별자·시행일·소관을 대조했습니다.

기존 사업 예비타당성조사 운용지침 1문서는 문단·표 형식이라 **조문 미분석**으로 남습니다. 별표·서식·부칙·기관 내규와 미수집 외부 법령의 본문·역인용은 전체 분석 범위가 아닙니다.

## 실행

프로젝트 요구사항에 맞는 Python 3.13 이상과 의존성이 설치된 환경에서 실행합니다. 법제처 인증은 기존 환경변수 또는 로컬 설정을 재사용합니다. 인증값과 수집 캐시는 Git에 넣지 않습니다.

```powershell
# 1단계: 기존 공공기관 묶음에 정의 차용 자료를 별도 추가
python -m scripts.collect_public_institution_scope --base-bundle <기존-공공기관-bundle.json> --stage inventory --phase scope
python -m scripts.collect_public_institution_scope --base-bundle <기존-공공기관-bundle.json> --stage bodies --phase scope
python -m scripts.collect_public_institution_scope --base-bundle <기존-공공기관-bundle.json> --stage build --phase scope

# 2단계: 상법과 설립법 추가
python -m scripts.collect_public_institution_scope --base-bundle output/public-scope/scope/bundle.json --stage inventory --phase privatization
python -m scripts.collect_public_institution_scope --base-bundle output/public-scope/scope/bundle.json --stage bodies --phase privatization
python -m scripts.collect_public_institution_scope --base-bundle output/public-scope/scope/bundle.json --stage build --phase privatization

# 3단계: 검토한 공식 정기 지정 발표 재수집·검증
python -m scripts.collect_public_designations --download

# 다른 10개 분야 자료를 보존하고 공공기관만 새 출력에 반영
python -m scripts.build_public_institution_site --base-site <기존-정적사이트-폴더> --destination output/public-scope-site
python -m http.server 8516 --bind 127.0.0.1 --directory output/public-scope-site
```

각 단계가 성공한 것을 확인한 뒤 다음 단계를 실행합니다. 기존 출력 폴더가 있는 정적 빌드 대상에는 덮어쓰지 않습니다. 로컬 Streamlit은 공공기관 묶음 경로로 `output/public-scope/privatization/bundle.json`을 지정하면 같은 근거 목록을 사용합니다.

이번 작업은 독립 체크아웃 `LawOrbit-PublicInstitutions`, 브랜치 `codex/public-institution-scope`에서 수행했습니다. 원래 작업 폴더는 보존하고, 검증한 변경을 후속 개정 점검과 함께 `static-web-2026-09-21-v2` 배포 묶음에 포함합니다. 노트북의 기존 Python 실행 경로가 없어 테스트에는 별도 출력 폴더의 공식 Python 3.13.15와 기존 설치 패키지를 읽어 사용했습니다. 원래 실행 환경은 수정하지 않았습니다.

## 후속 개선안: ALIO 기관정보 연계 (미구현)

2026-09-21 확인한 [알리오플러스 공식 API 안내](https://www.alioplus.go.kr/openapi/openAPI.do)는 시설·행사·사업·기관정보 제공을 명시합니다. 공개 안내만으로 전체 지정·해제 이력, 실제 효력 발생일, 기관 내규 전문까지 API로 제공된다고 확인할 수는 없습니다.

후속 목표는 **기관을 선택해 관련 규정의 확인 후보를 보는 기능**입니다.

1. 기관정보 API의 식별 코드·기관명·기관 유형·주무부처·갱신일 제공 여부를 문서와 실제 응답으로 확인합니다.
2. 제공되는 기관정보를 공식 지정 발표와 대조해 보완합니다. API의 현재 유형으로 과거 유형·효력일을 역산하지 않습니다. 기관명 변경·통폐합은 확인된 이력만 연결합니다.
3. 기관별 공시·내규 원문 연결은 해당 항목의 API와 원문 이용 조건을 확인한 뒤 범위를 정합니다. 경영정보 전체를 제공한다고 가정하지 않습니다.
4. 도입한다면 수집 환경에서 자료를 갱신해 정적 파일로 배포하는 방식을 우선 검토합니다. 방문자 브라우저에 인증키를 넣지 않는 설계입니다.

사용자 요청에 따라 **연계 구현·API 신청·인증키 발급·자동화는 실행하지 않았습니다.** 현재 법령 연결과 지정 변경 기능은 ALIO API 인증키 없이 동작합니다. 공식 ALIO 자료실에서 배포하는 PDF를 출처로 이용하는 것과 ALIO API를 연계하는 것은 구분합니다.
