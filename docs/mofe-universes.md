# 재정경제부 업무 분야 확장 — 공공기관·관세통관·국고회계

2026-09-21 법제처 API 수집 판본을 사용한 **로컬 미리보기**입니다. 기존 공개 사이트에는 배포하지 않았습니다.

## 판단: 세 분야의 효용은 같지 않다

| 분야 | 판단 | 구체적으로 줄이려는 수고 | 지원하지 않는 업무 |
|---|---|---|---|
| 관세·통관 | 독립 탐색 도구로 가장 타당 | 관세법 조문에서 통관·원산지·환급 집행규정의 인용 근거를 왕복 확인 | 관세액 산정, HS 분류, 국가별 협정 요건, 수입 가능 여부 판정 |
| 공공기관 | 계약·회계·사업관리의 근거 확인으로 범위를 한정하면 유용 | 공공기관운영법과 계약사무규칙·회계사무규칙·총사업비 지침을 함께 읽기 | 현행 경영평가·인사·보수·기관별 내규의 종합 검토 |
| 국고·회계 | 법적 근거를 찾는 보조도구로 유용 | 선급·개산급, 국가회계기준, 채권 이행연기의 법률·하위규정 확인 | 전표·분개 판단, 결산 오류 탐지, 예산편성 심사 |

연결 수와 그래프의 화려함을 효용 점수로 쓰지 않습니다. 각 분야에서 **서로 다른 문서의 실제 조문과 인용 문구를 열어 볼 수 있는 업무 질문을 2개 이상** 확인한 경우에만 미리보기를 생성합니다. 이는 기능의 최소 검증 조건이며, 담당자 사용성 평가나 개정 필요성 판정을 대신하지 않습니다.

현재 3개 분야마다 질문 3개씩, 총 9개를 검증했습니다. 앞으로 실제 담당자가 질문을 해결하는 시간을 줄이지 못한다면 해당 진입점은 축소하거나 통합해야 합니다. 특히 공공기관 분야를 인사·평가 도구로 확대하려면 최신 지침·편람의 판본 관리와 구조 분석이 먼저 필요합니다.

## 실제 수집과 분석 범위

| 분야 | 수집 문서 | 조문 분석 문서 | 분석 조문 | 문서 간 인용 근거 |
|---|---:|---:|---:|---:|
| 공공기관 | 12 | 11 | 350 | 136 |
| 관세·통관 | 45 | 44 | 3,100 | 4,621 |
| 국고·회계 | 42 | 22 | 861 | 467 |
| 합계 | 99 | 77 | 4,311 | 5,224 |

문서 간 인용 근거는 같은 문서 안의 인용을 제외하고, 대상 조문이 수집 본문에 존재하는 근거를 센 수입니다. 항·호, 같은 조문의 여러 인용 문구가 별도 근거가 될 수 있습니다. 법령 수·연계개정 의무 수·검증 정확도와 같지 않습니다.

- **공공기관:** 공공기관운영법 등 법령 6개 + 선정 행정규칙 6개. 최신 경영지침·예산운용지침·경영평가편람은 미수집·미분석입니다. 현행 공식 자료실로 가는 링크를 별도로 제공합니다. 예타 운용지침 1개는 본문만 보관하고 조문 연결 미분석으로 표시합니다.
- **관세·통관:** 관세법·FTA관세법·관세환급특례법과 각 시행령·시행규칙 9개 + 선정 집행규정 36개. 관세청 내부 조직·인사규정을 포함한 전수 수집이 아닙니다. 원산지(포괄)확인서 고시 1개는 조문 미분석입니다.
- **국고·회계:** 국고금·국가회계·국가채권·국채·수입인지·정부보관금 관련 법령 17개 + 선정 행정규칙 25개. 회계처리지침 19개 및 국고자금 집행지침은 문단·표 형식이므로 조문 미분석입니다. 원문과 공식 링크는 읽을 수 있습니다.

소관은 수집 응답의 **재정경제부**를 기준으로 검사합니다. 관세·통관의 집행규정은 **관세청**도 허용합니다. 기획예산처 소관 및 공동 소관 법률을 기본 수집에 혼합하지 않습니다. 국가재정법 등 미수집 법령의 인용은 외부 근거로 보존합니다. 기존 국세·조달계약 자료를 자동 합치지 않습니다.

## 바로 확인할 업무 질문

- **공공기관운영법 제39조:** 계약·회계 규칙은 어떤 법률 조문에 근거하는가? 계약사무규칙 제1조·제15조 등과 회계사무규칙의 실제 역인용을 확인합니다.
- **공기업·준정부기관 회계사무규칙 제19조:** 세부 회계기준의 근거는? 회계기준 제1조에서 읽습니다.
- **공공기관운영법 제40조:** 사업예산과 총사업비 관리 근거는? 시행령과 총사업비관리지침에서 확인합니다. 예타지침을 분석했다고 표시하지 않습니다.
- **관세법 제226조:** 세관장 확인은 어느 집행규정과 연결되는가? 다른 문서의 수집 조문 37개를 확인합니다. 시행령 제233조의 확인 절차, 세관장확인 고시 등의 인용을 직접 읽습니다.
- **FTA관세법 제12조:** 원산지인증수출자 규정과 운영 고시는 어떻게 이어지는가?
- **관세환급특례법 제9조:** 관세환급의 시행령·환급 고시 근거는?
- **국고금 관리법 제26조:** 미리 지급하는 경비의 법적 근거와 하위 규정은?
- **국가회계법 제11조:** 국가회계기준 규칙은 어느 법률 조문에 근거하는가?
- **국가채권 관리법 제27조:** 이행연기특약은 어떤 시행령 규정과 이어지는가?

## 화면과 분석 원칙

- 분야 순서는 국세 → 조달계약 → 관세·통관 → 외환 → 국유재산 → 공공기관 → 국고·회계 → 금융 → 지방세 → 국토건축주택 → 환경화학안전입니다. 재정경제부 업무와 관련된 분야를 먼저 배치하되, 연결 수나 실제 이용률의 순위로 해석하지 않습니다. 기존 무료 정적 열람과 로컬 Streamlit 모두 같은 분석 엔진을 재사용합니다.
- 분야 상단에 검증한 **업무 질문으로 시작**을 두고, 지도·본문·인용 원문을 바로 엽니다.
- 관련 조문 클릭은 **본문 읽기 창**을 엽니다. 검토 기준을 유지하며, 별도 버튼으로만 기준 조문을 바꿉니다.
- 분야별 법령·조문 검색, 선택 상태, 캐시와 출력 경로를 분리합니다. 복수 업무 태그는 제목·본문 키워드에 따른 탐색 보조이며 법적 적용범위 판정이 아닙니다. 다른 태그의 실제 연결은 **분야 밖 관련 조문**으로 표시합니다.
- 전체 지도에는 수집 문서 간 근거가 있는 연결을 표시하며, 같은 법률·시행령·시행규칙 사이의 연결도 포함합니다. 지도 위 작은 조문 점은 표시 수가 제한되고 본문 목록에서는 전체 분석 조문을 읽을 수 있습니다.
- 미수집 외부 법령의 본문·역인용은 검사했다고 표현하지 않습니다. 미분석 문서는 지도에 가짜 조문을 만들지 않습니다.

## 실제로 발견하여 수정한 연결 오류

새 세 분야만 명시적으로 적용하는 정책입니다. 기존 분야의 원문·그래프는 다시 쓰지 않았습니다.

1. 개인투자용국채규정의 **같은 법 시행령**을 기본 법률인 국채법 시행령으로 잘못 읽지 않고, 해당 문맥의 조세특례제한법 시행령 등으로 해석합니다.
2. 별도 이름의 계약사무규칙에 등장하는 **법 제39조**는 수집 본문의 약칭 정의를 근거로 공공기관운영법에 연결합니다.
3. **「법률명」(이하 "약칭")**처럼 짧게 선언한 별칭과 제목이 끼어 있는 조문 범위를 처리합니다.
4. **법령·고시 명칭 안의 조문번호**는 그 자체를 조문 인용으로 세지 않습니다.
5. 따옴표로 따온 문구 속 조문, 장·절 인용의 제외 조문, 수집 판본에 존재하지 않는 대상은 추측으로 연결하지 않고 원문 확인 목록에 보존합니다.

아직 상대 참조와 복잡한 준용 문구를 완전히 해석하지 않습니다. 관계가 없다는 화면은 영향 없음의 판정이 아닙니다. 별표·서식 본문·부칙, 문장 유사성, 암묵적 제도 의존성, 변경 전후의 재연결 판단도 이번 범위 밖입니다.

## 수집·실행

프로젝트 루트에서 기존 인증 환경변수 또는 로컬 설정을 재사용합니다. 인증값은 저장소·배포물에 포함하지 않습니다.

```powershell
python -m unittest scripts.test_mofe_domains -q
python -m scripts.collect_mofe_universes --domain all --stage inventory
python -m scripts.collect_mofe_universes --domain all --stage bodies
python -m scripts.collect_mofe_universes --domain all --stage build
```

각 단계는 같은 날짜로 실행하세요. 날짜를 넘겨 재개할 때는 세 단계 모두 `--date YYYYMMDD`로 수집 기준일을 맞춥니다. 실패하면 기존 bundle을 보존하고, 실행 중인 잠금이 있으면 다른 수집을 중단하지 않습니다. 기존 bundle은 교체 전에 history에 보관합니다.

```powershell
python -m scripts.build_mofe_site --base-site output/static-forex-preview --destination output/static-mofe-new
python -m scripts.validate_static_galaxies output/static-mofe-new
python -m http.server 8514 --bind 127.0.0.1 --directory output/static-mofe-reviewed
```

빌드는 기존 출력 폴더를 덮어쓰지 않습니다. 현재 완성 미리보기는 `output/static-mofe-reviewed`, 주소는 `http://127.0.0.1:8514/`입니다. 주소는 이 노트북에서 서버가 실행 중일 때 열립니다.

로컬 앱은 `python -m streamlit run app.py`로 실행합니다. 세 분야의 수집/분석 결과는 각각 `output/public_institutions-universe`, `output/customs-universe`, `output/treasury-universe`에 있습니다. 각 폴더의 assessment.json, summary.json, staging의 inventory.json에서 포함·제외·미분석 자료를 확인할 수 있습니다.

## 검증과 미실행

검증 로그와 원래 자료의 해시 대조 결과는 `output/mofe-expansion/verification.json`에 기록합니다. 오프라인 48개 모듈을 통과했고, 이 안의 unittest 247개 중 11개는 해당 체크아웃에 필요한 원본 자료가 없어 건너뛰었습니다. 기존 5개 분야의 실제 자료를 사용한 정적 분석 대조 등 별도 6개 테스트와 최종 화면 상태 테스트 2개도 통과했습니다. 브라우저에서는 1365×900, 390×844 폭을 확인했습니다.

- 범위·소관 검증, 원문 위치와 인용 문구 일치, 조문 존재, 실제 사례의 직접·역인용, 자료 부재 시 대체 금지.
- Python 분석과 브라우저의 조·항·호 범위 결과 일치, 분야별 검색·선택 상태 분리.
- 기존 기능 포함 오프라인 테스트, 정적 배포물의 모든 참조 파일·체크섬 검증.
- 실제 브라우저에서 세 분야와 원문 창·범위 안내·모바일 폭을 확인.
- 기존 수집 묶음 7개와 기존 정적 8개 분야의 데이터 파일 19,243개, manifest 항목이 동일함을 해시로 확인. 배포물 19,566개 파일에서 인증값이 없는지 검사.

**미실행/미구현:** 실제 담당자 대상 사용성 시험, 휴대전화 실기기 터치 시험, 새 세 분야의 예약 갱신, 지침 PDF/표의 구조 분석, GitHub/GitLab 실제 배포. 커밋·푸시는 하지 않았습니다.
