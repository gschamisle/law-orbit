## 검사기 결과를 해석할 때

첫 CLI 실행은 새 표본에 없는 `regression_fixtures`를 필수로 읽어 보고서 작성 전 중단했다. 기대값을 바꾸거나 호환 복사본을 만들지 않았다. 기존 검사기의 비교 함수를 직접 호출한 보조 결과와 개별 공개 행을 읽어 위 차이를 분류했다.

그 시점 검사기는 서식 누락을 제대로 판정하지 못하고, 표의 호를 일반 조문 호처럼 읽으며, 번호 없는 위임의 음성대조를 해당 문구가 아니라 조문 전체 연결 유무로 판단했다. 따라서 해당 실행의 matched 수를 표본 통과 수로 발표하지 않는다. 개선된 검사기의 최종 결과는 별도 보고서로 기록하며 위의 수정 전 관찰과 구분해야 한다.

역사적 판본 조건, 표 안 번호, 서식의 가지·세부번호, 현재 저장된 대상 본문 존재 여부는 서로 다른 검사다. 검토 후보/미수집 표시만으로 잘못된 연결이라고 판단하지 않으며, 반대로 검토 표시가 있어도 다른 법령으로 향하는 클릭 대상은 별도 결함이다.

## 보완 시 우선순위

1. 표의 끊긴 인용과 구법 괄호 뒤의 법령 소속을 잃었을 때 자기 문서로 확정하지 않는다. 복원이 불확실하면 원문 근거를 보존한 확인 사항으로 남긴다.
2. 같은 열거 안의 서식 소속, 가지번호와 괄호 세부번호를 보존한다. 문서 메타데이터가 부족하더라도 번호를 짧게 바꾸어 다른 서식으로 연결하지 않는다.
3. 표 번호가 사이에 있는 법/영의 열거 및 같은 항 참조에서 소속을 보존한다. 표 안 세부 분석은 별도 기능 범위로 명시할 수 있다.
4. 구법 인용을 현행 동일 번호로 이동시키는 것만으로 완료로 보지 않는다. 옛 판본 조건의 표시·원문 경로가 별도 필요하다.
