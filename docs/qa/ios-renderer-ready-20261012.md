# iPhone/Safari 지도 초기화 점검 — 2026-10-12

## 재현과 원인

제보는 최신 iOS로 추정되는 기기에서 카카오톡과 Safari 모두 지도가 빈 화면으로 남는 현상이었다. 기사 본문과 연결 목록은 표시되지만 지도는 기본 제목 `국세`와 초기 300×150 캔버스 상태에 머물렀다.

수정 전 공개 자료 묶음을 로컬에서 실행하고 Playwright WebKit 26.5(revision 2336), iPhone 13 화면·터치 설정으로 같은 증상을 재현했다. 부모 화면의 iframe `load` 콜백에서 `postMessage`를 호출하면 이 환경에서는 수신 이벤트의 `source`가 부모 대신 자식 창으로 관측됐다. origin은 맞았지만 기존 `event.source === parent` 검사를 통과하지 못해 지도 초기화가 실행되지 않았다. JavaScript 오류는 발생하지 않았다.

## 변경

지도는 수신 핸들러를 설치한 뒤 `galaxy-ready`를 알리고, 부모 창의 메시지 핸들러에서 현재 지도 자료를 전달한다. 부모는 현재 iframe, 발신 창, 정확한 origin, 메시지 종류를 확인한다. 자식도 기존 부모 창·origin 검사를 유지한다. 다른 iframe과 교체 전 iframe의 메시지는 받지 않는다.

새 브라우저 파일·렌더러 URL·서비스 워커 캐시 버전을 사용하며 새 모듈과 실제 렌더러 URL도 오프라인 화면 자원에 포함한다.

## 확인 결과

- 수정 전: `source === parent`가 false, `source === window`가 true, 초기 300×150 캔버스와 기본 제목 유지.
- 수정 후: `source === parent`가 true, `법인세법 제5조`의 `조문 연결 지도`와 716×1260 캔버스, 별과 연결선 표시.
- WebKit / Edge Chromium × 모바일 / 데스크톱 네 조합 통과. 조문 지도, 연결 조문 본문 열기와 출발 조문 유지, 전체 지도, 보건·의료 전환을 확인했다. 모바일은 기본 스크롤 모드와 지도 조작 모드 전환을 확인했다. 페이지 오류는 없었다.
- 렌더러 메시지 검사 5개 통과. 정상 수신, 외부 origin·형제 창·빈 발신자·알 수 없는 메시지 거부, 교체된 지도와 재로딩을 다룬다.
- 등록된 오프라인 Node 모듈 13개와 관련 Python 모듈 4개 완료. 수집 자료를 요구하는 Python 사례 1개는 환경 조건에 따라 생략했고, 별도로 완성된 공개 자료 묶음 전체 검증을 통과했다.
- 공개 묶음 검증: 6,114개 물리 파일, 20,700개 논리 자료 파일, 11,669개 문서, 275,310개 조문. 기존 자료·manifest 파일 6,079개가 바이트 단위로 같고 자료 버전은 `11ae6b37df2529f11750`이다.
- 소스에서 새로 생성한 브라우저 화면과 배포 묶음의 파일 일치 검사, Git 공백 오류 검사 통과.

## 검증 범위

실제 아이폰 하드웨어를 직접 조작한 결과는 아니다. Windows에서 공식 Playwright WebKit 엔진과 모바일 설정으로 재현·검증했다. 엔진의 Windows 의존성 사전 검사만 건너뛰었으며 웹 보안 정책은 해제하지 않았다. 브라우저 비교 검사는 서비스 워커를 차단해 실행했고, 저장 캐시와 출처 경계는 별도 오프라인 테스트로 확인했다. 배포 후 제보 기기에서 새로고침하여 확인할 필요가 있다.

로컬 증거는 `output/ios-renderer-audit/`의 `before.json`, `after.json`, `after.png`, `flows.json`, 시험 로그와 전체 자료 검증 보고서에 보관한다. 공개 자료와 무관한 로컬 파일을 배포 묶음에 넣지 않는다.
