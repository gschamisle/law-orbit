## 화면 구성

### 1. 법령 탐색

최상단의 **헌법**과 그 아래 **분야별 법령**을 구분합니다. 헌법은 아래 표의 업무 분야와 별도로 배치하고, 각 분야에 바로 접근할 수 있게 유지합니다.

국세를 시작으로 재정경제부 업무와 관련된 분야를 먼저 배치하고, 금융·지방세·국토·건축·주택·환경·화학·안전으로 이어집니다. 조달·계약·관세통관처럼 법령과 집행규정을 자주 함께 읽는 분야를 앞에 두었습니다. 활용도를 예상한 탐색 순서이며, 실제 이용 통계에 따른 순위나 각 분야 모든 문서의 단독 소관을 뜻하지 않습니다. 관세·통관, 공공기관, 국고·회계는 인용 근거를 확인한 업무 질문으로 시작하며, 종합적인 경영평가·관세 판단·결산 검증 도구를 표방하지 않습니다.

### 2. 후속 개정 점검 (국세·공공기관)

공개 웹에서 법률 또는 시행령을 선택한 뒤 **후속 개정 점검 · 위임사항**을 엽니다. 대통령령·총리령·부령에 위임한 문구와 기존 하위법령의 인용 근거를 함께 읽고, 대응 인용이 확인되지 않은 후보도 살펴봅니다. 이전 판본이 있는 갱신본에서는 위임의 추가·변경·삭제와 조문 내용 변경을 대조합니다.

법인세법·소득세법·조세특례제한법은 공식 직전 시행판과 현재 공개본을 대조합니다. 당시 하위법령과 역인용 자료는 미수집이며, 현재 인용은 재검토 후보입니다. 나머지 법령에서 과거와 대조하지 않은 항목은 **이전 판본 미대조**로 표시합니다. 같은 조문 번호를 인용한다는 이유만으로 새 내용에 대응한다고 판정하거나, 인용 미확인을 개정 누락으로 확정하지 않습니다. [실제 판본·검증 사례](tax-delegation-history.md).

국세의 미수집 법령 인용은 출처 조문별 확인 목록에서 볼 수 있습니다. 깨진 법령명·대상이 불명확한 참조는 해석 확인 항목으로 구분합니다. 법인세법 시행규칙 별표 5·6과 조세특례제한법 시행령 별표 6은 본문과 명시적 인용을 제공합니다. 표의 적용 조건·내용연수·세액공제를 계산하거나 판정하지는 않습니다. [미수집 인용](tax-external-references.md) · [선정 별표](tax-annexes.md).

비공개 개정안은 로컬 전용 메뉴에서 한 조문의 개정 전후 본문을 비교합니다. 공개 사이트에 개정안을 입력하거나 업로드하지 않습니다. [지원 범위·판본 보존·실행 방법](delegation-review.md).

### 3. 개정안 파일 검토 (국세 · 로컬 전용)

국세 개정안 파일을 여러 개 올리고 두 가지를 대조합니다.

- **번호 이동에 따른 인용 정비:** 항·호·목 번호가 바뀔 때 기존 번호를 인용하던 조문의 정비 후보를 찾습니다.
- **병행개정 대응 조문:** 등록된 대응 관계를 바탕으로 함께 검토할 조문을 찾습니다.

이 메뉴는 국세용 인용 그래프와 병행개정 대응표를 사용합니다. 금융 등 다른 분야의 자료를 수집해도 **해당 분야의 개정안 자동 검토까지 지원하는 것은 아닙니다.** PDF·HWP·HWPX·Markdown·텍스트 파일을 받으며, 문서 형식별 추출 가능 여부에 따라 읽기 결과가 달라질 수 있습니다.

## 법령 탐색에서 할 수 있는 일

- **특정 조문에 집중:** 수집 목록에서 법령·규정과 조문·항호목을 선택하면 해당 조문의 인용·역인용 연결을 강조합니다. 수집 본문에서 조문을 찾아 불러올 수도 있습니다.
- **공공기관 정의·적용범위:** 공운법 정의 차용과 확인된 경유 관계의 포함·제외 조건, 공기업 민영화법 특례, 검토한 정기 지정 변경을 공식 출처와 함께 확인합니다. 전체 기관 명부나 기관별 의무 판정은 지원하지 않습니다.
- **인용 근거 확인:** 범위·나열형 인용을 해석하고, 원문 문맥·시행일·공식 출처를 함께 보여 줍니다. 문맥 확인이 필요한 후보는 구분합니다.
- **별표·서식 원본 확인:** 조문이 가리키는 별표·서식 번호와 공식 첨부파일을 연결합니다. 파일 주소가 없으면 소유 법령 페이지로 안내합니다. 별표 제목의 관련 조문과 본문 인용을 구분하며, 별표 내부 분석은 기존 검증 자료에 한정합니다. [범위·검증 안내](annex-reference-links.md).
- **분야 밖 연결 확인:** 업권·세부 분야는 복수 태그로 관리합니다. 수집한 다른 분야로 이어지는 조문은 ‘분야 밖 관련 조문’으로 표시합니다.
- **외환·금융 함께 읽기:** 정적 웹 앱에서 외환과 은행·증권 등 금융 규정 사이의 명시적 인용을 대조합니다. 분야별 전체 지도와 선택 상태를 유지하면서 상대 분야의 본문과 역인용을 확인합니다. [사용 방법·판본·한계](forex-finance-links.md).
- **미수집·미분석 구분:** 자료가 없는 분야는 미수집으로 안내합니다. 외부 법령 인용이나 본문 분석이 안 된 자료는 그 상태와 공식 링크를 남깁니다.
- **오프라인 탐색·공유:** 수집된 법령과 연결을 열람하고 독립 HTML로 내려받을 수 있습니다. 모바일은 기본 스크롤 모드이며 지도 조작을 켜면 회전·두 손가락 확대·축소를 사용할 수 있습니다. 조작 종료로 스크롤 모드로 돌아갑니다. 상단 버튼은 전체 보기·전체 화면·지도 조작으로 구성하며 소리·재생 전환 버튼은 제공하지 않습니다. 기기의 동작 줄이기 설정을 존중합니다.

인용 탐색은 파서와 저장된 그래프를 사용하며 런타임 LLM 호출이 필요하지 않습니다. 분야 사이의 전체 자료를 자동으로 합치지 않습니다.

## 해석할 때 알아둘 점

이 도구는 **수집 범위 안의 검토 후보와 근거**를 보여 줍니다. 연결이 있다고 반드시 함께 개정해야 하는 것은 아니며, 연결이 없다고 영향이 없다고 확정할 수도 없습니다.

- 전국 조례를 비롯한 모든 관련 자료의 완전 수집을 보장하지 않습니다. 분야별 문서에서 수집 범위·미분석 항목을 확인하세요.
- 별표·첨부파일·부칙, 의미만 비슷하고 명시적 인용이 없는 관계 등은 분야별 지원 수준이 다릅니다.
- 화면의 거리·색상·연결 건수는 법적 영향의 크기나 개정 의무의 수를 뜻하지 않습니다.
- 개정안 검토용 자료와 법령 탐색용 자료는 별도입니다. 수집 자료 갱신이 국세 개정안 검토의 모든 자료 갱신을 의미하지 않습니다.

## 설치와 실행

Python 3.13 이상과 [uv](https://github.com/astral-sh/uv)를 사용합니다. 로컬 후속 개정 비교에는 Node.js 22 이상도 필요합니다. 공개 웹 열람에는 설치가 필요하지 않습니다.

```bash
uv sync
uv run streamlit run app.py --server.port 8503
```

Windows에서는 프로젝트 폴더의 `./start.ps1`로 실행할 수도 있습니다. 실행 후 `http://127.0.0.1:8503/`에서 엽니다.

### 인증 설정

자료 수집·현행본 확인에는 법제처 Open API 인증값이 필요합니다. 기존 환경변수 또는 프로젝트 루트의 `.env`에 `LAW_API_KEY`를 설정하세요. 분야별 수집기는 `LAW_OC`도 지원합니다. 인증값을 코드나 Git에 넣지 않습니다.

```env
LAW_API_KEY=법제처_인증값
```

이미 수집된 자료의 법령 탐색에는 API 호출이 필요하지 않습니다. `OPENAI_API_KEY`·`ANTHROPIC_API_KEY`는 선택적 보조 기능·일부 자료 구축에 사용하며, 기본 법령 탐색과 국세 개정안 대조에는 필요하지 않습니다. 설정 항목은 [.env.example](../.env.example)을 참고하세요.

## 검증

```bash
uv run --frozen python -m scripts.check_test_inventory
uv run --frozen python -m scripts.run_offline_tests
uv run --frozen python -m scripts.run_offline_tests --runtime node
```

파서·인용 분석·데이터 분리·화면 상태 등을 오프라인으로 검사합니다. [명시적 시험 목록](../scripts/test_suites.json)은 오프라인·수집자료·API 로컬 전용 시험을 구분합니다. 새 시험 파일이 목록에 없으면 실행 전에 실패하며, 발견한 파일을 임의로 실행하지 않습니다. API 로컬 전용 시험은 위 명령으로 실행되지 않습니다.

별도 수집자료 시험과 일부 혼합 시험은 필요한 로컬 자료가 없으면 이유를 표시하고 건너뜁니다. 자료가 있는데 검증에 실패한 경우에는 건너뛰지 않습니다. CI는 uv 0.12.10과 `uv sync --locked`로 잠금 파일 일치 여부도 확인합니다.

GitHub Actions의 [오프라인 테스트](../.github/workflows/offline-tests.yml)에서도 같은 스위트를 실행합니다.

## 내부자료 보호

인증값과 업로드한 개정안은 공개하지 않습니다. 수집 원본은 로컬에 보관하며, 공개 출처·본문·인용 근거만 검증하여 정적 열람 자료로 게시합니다. 업로드 파일은 Git에서 제외한 `data/uploads/`에 보관합니다. 기존 수집 자료와 원문을 유지한 채 검증된 갱신 결과를 분야별로 반영합니다.

의견 문서 등 기존 Git 추적 산출물과 정적 사이트의 공개 경계는 [공개자료 점검](public-materials-audit-20261004.md)에서 확인합니다. 제외 규칙만으로 이미 추적된 파일이 숨겨지지는 않습니다.
