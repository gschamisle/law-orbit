# 후속 개정 점검 — 국세·공공기관 우선 적용

## 화면과 범위

- 공개 열람판: 국세·공공기관에서 법률 또는 시행령을 선택한 뒤 **후속 개정 점검 · 위임사항**을 엽니다. 내부 개정안 입력 칸은 공개판에 없습니다.
- 로컬 Streamlit: **후속 개정 점검 (국세·공공기관)** 메뉴에서 개정 전후 한 조문의 전체 본문을 비교합니다. 기존 국세 개정안 파일 검토는 유지됩니다.
- 분석 엔진은 `web/delegation.mjs` 하나를 공유합니다. 공개판은 브라우저에서, 로컬판은 Node.js 22 이상을 통해 같은 코드를 실행합니다. 입력 본문은 외부 AI·API로 전송하거나 파일로 저장하지 않습니다. 로컬 앱은 루프백 주소에 바인딩해 사용합니다.

## 확인하는 사항

1. 대통령령·총리령·부령으로 정하도록 한 명시적 문구와 원문 위치.
2. 이전 판본이 있는 경우 위임 추가·변경·삭제, 동일 문구의 조 번호 이동 후보.
3. 위임 문구가 같아도 조문 내용이 바뀐 경우, 위임 문구 없이 바뀐 조문의 하위법령 인용.
4. 법률 → 시행령·시행규칙, 시행령 → 시행규칙의 기존 인용 근거. 항·호·목 대조는 기존 인용 범위 엔진의 결과를 재사용합니다.
5. 종전 판본의 인용 근거와 현재 수집 근거를 구분합니다. 조 번호 이동을 이유로 기존 그래프의 연결을 자동 변경하지 않습니다.

‘대응 인용 미확인’은 개정 누락 확정이 아닙니다. 기존 규정으로 충족되거나, 자료가 미수집·미분석·미갱신일 수 있습니다. 시행일 차이만으로 판본 불일치나 개정 누락을 확정하지 않습니다. 별표·서식·부칙, 명시적 문구 없는 의미상 위임, 업무량·정원 적정성은 분석 범위가 아닙니다. 같은 조문을 인용한다는 사실만으로 특정 위임이 이행됐다고 판정하지 않습니다.

## 판본 보존과 다음 갱신

첫 실행은 현재 수집본을 **첫 비교 기준**으로 보관합니다. 과거 판본을 확보하지 못했으므로 ‘신규 위임’으로 표시하지 않습니다. 첫 공개판은 이 상태입니다.

법제처 자료를 수집·분석한 다음, 새 정적 사이트를 빌드할 때 직전 사이트를 전달합니다.

```powershell
python -m scripts.build_static_galaxies --source-root <수집자료-폴더> --destination <새-사이트-폴더> --previous-site <직전-사이트-폴더>
```

이미 빌드한 사이트에 비교 기준을 붙이고 새 화면을 적용하려면 다음을 사용합니다.

```powershell
python -m scripts.build_delegation_site --base-site <새로-수집한-사이트> --destination <새-출력-폴더> --previous-site <직전-사이트>
```

공공기관만 갱신하는 `build_public_institution_site`는 `--base-site`를 이전 판본으로 이용합니다. 본문·시행일이 변하지 않은 재빌드에서는 마지막으로 달랐던 판본을 유지합니다. 변경이 발생하면 그 직전 본문·인용을 새 비교 기준으로 남깁니다. 변경 확인을 담당자가 승인·완료 처리하는 기능과 다수 판본 이력 관리는 아직 없습니다.

자료를 수집하는 것과 공개 사이트를 갱신·배포하는 것은 별도 단계입니다. 이번 변경은 기존 주간 수집 예약의 대상·주기나 자동 배포 설정을 변경하지 않습니다. 새 자료와 비교 기준을 포함한 사이트를 배포해야 이용자 화면에 판본 비교가 반영됩니다.

새 출력 폴더만 허용하며 원래 자료를 수정하지 않습니다. 국세·공공기관 카탈로그에 비교 기준만 추가하고 기존 법령 본문·인용·지도와 다른 9개 분야의 카탈로그는 보존합니다. 기준 자료도 압축 파일 해시를 검증합니다.

## 로컬 비교

기존 앱의 전용 메뉴 또는 독립 화면으로 실행합니다. 독립 화면은 다음처럼 로컬 주소에 한정합니다.

```powershell
python -m streamlit run ui/delegation_local_app.py --server.address 127.0.0.1 --server.port 8518
```

1. 국세 또는 공공기관, 법률 또는 시행령을 고릅니다.
2. 수집 본문을 불러오거나 개정 전후 조문 전체를 입력합니다.
3. 신설·삭제 조문은 해당 항목을 명시적으로 선택합니다. 발췌문·개정 지시문은 지원하지 않습니다.
4. 결과의 위임 문구와 현재 수집 자료의 하위법령 인용을 함께 확인합니다. 입력한 미래 개정안의 시행일이 저장 인용과 일치한다고 가정하지 않습니다.

로컬 입력의 완전성·사실성은 사용자가 확인해야 합니다. 형식 검증은 조문 내용이 중간에 생략됐는지까지 보증하지 않습니다. 일반 공개판에서 내부 문서를 받는 기능은 추가하지 않았습니다.
