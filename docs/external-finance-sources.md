# 수출·해외사업 금융과 KIC 위탁·운용

2026-11-18 법제처 공식 API에서 네 근거법과 실재 하위법령 **10개, 334개 조문**을 수집했습니다. 법령의 고유 식별번호, 판본 일련번호, 시행일, 소관 부처를 목록과 본문 사이에서 대조했습니다.

## 화면의 구분

- **수출·해외사업 금융**: 한국수출입은행법·무역보험법·대외경제협력기금법과 하위법령 8개, 275개 조문. 수출입 금융·보증, 해외사업·투자, 무역보험·기금, 대외경제협력기금으로 탐색합니다.
- **외환의 KIC 위탁·운용 길잡이**: 한국투자공사법과 시행령 2개, 59개 조문. 위탁 주체, 위탁계약, 운용 범위·방식, 감독·공시·회수의 근거를 읽습니다. KIC를 수출기업에 대한 금융지원기관으로 분류하지 않습니다.

기관명만으로 같은 업무라고 판단하지 않습니다. 대출·보증, 보험, 개발협력기금과 공적 외화자산 위탁운용은 각각 근거와 대상이 다릅니다. 길잡이의 단계와 안내선은 자료를 읽는 순서이며, 모든 사건에 적용되는 법정 절차나 실제 인용선이 아닙니다.

## 현행과 시행 예정의 분리

현행 목록(`nw=3`)과 시행 예정 목록(`nw=2`)을 각각 조회합니다. 기준일 이후 시행하는 판본의 본문은 현행 자료에 섞지 않습니다.

한국수출입은행법은 **2026-11-30 시행 예정판, 일련번호 283351**이 있지만, 2026-11-18 기준 본문은 **2026-07-22 시행판, 일련번호 285527**입니다. 일련번호가 더 크거나 공포일이 더 늦다는 이유만으로 현행을 선택하지 않습니다. 예정판은 `inventory.json`과 `source.json`의 `scheduled`에 메타데이터로 보존합니다. 해당 시행일 이후에는 목록·본문을 다시 확인하고 길잡이 근거도 재검증해야 합니다.

## 검증한 탐색 사례

| 무역보험법 제31조제1항제4호 | 시행령 제3조에서 인용 | 기금 조성 재원의 추가 범위 확인 |
| 대외경제협력기금법 제9조제2항 | 시행령 제4조에서 인용 | 수출입은행장에 대한 기금 관리·운용 사무 위탁 근거 확인 |

무역보험법 제30조는 **기금의 설치**, 제31조는 **기금의 조성**입니다. 업무 예시는 실제 표제와 인용을 대조해 제31조로 정했습니다.

새 수출 분야 8개 법령의 자체 분석 결과, 문서 사이의 조문 인용 근거는 48건, 미수집 외부 인용은 80건입니다. 이 숫자는 원문 위치와 대상별 근거 수이며, 서로 다른 법령 수나 개정 의무 수가 아닙니다. 수집한 대상의 조문을 찾지 못한 연결은 0건이지만, `같은 조`, `같은 항`과 같은 상대 참조 6건은 문맥 검토 대상으로 남겼습니다. 기존 분야와 합친 연결 건수는 별도의 통합 빌드 결과입니다.

## 실행 순서와 산출물

아래 명령은 저장소 루트에서 실행합니다. 기존 환경변수 또는 로컬 설정의 인증값을 사용하며 값은 출력하거나 산출물에 저장하지 않습니다.

```powershell
uv run --frozen python -m scripts.collect_external_finance --stage inventory --as-of 20261118
uv run --frozen python -m scripts.collect_external_finance --stage bodies --as-of 20261118
uv run --frozen python -m scripts.collect_external_finance --stage build --as-of 20261118
uv run --frozen python -m scripts.test_external_finance_collection
```

기본 출력 경로는 `output/external-finance-20261118`입니다. `--dest`로 같은 날짜 접두사를 가진 새 폴더를 지정할 수 있습니다. 날짜가 다른 재수집은 해당 실행일을 사용합니다.

1. `inventory.json`: 현행 10개 법령과 시행 예정 메타데이터, 조회 범위·페이지 해시.
2. `source.json`: 본문 식별번호·시행일·소관·해시를 검증한 10개 법령 원문.
3. `kic-source.json`: 외환에 재사용할 KIC 2개 법령. 통합 단계에서 외환 분야의 식별자와 관계를 생성합니다.
4. `validated-bundle.json`: KIC를 제외한 수출 분야 8개 법령, 인용 분석과 실무 사례 검증 결과.
5. `summary.json`, `runs/`: 범위·검증 요약 및 단계별 실행 기록.

단계별 결과는 내용을 바꾸어 덮어쓰지 않습니다. 오류나 충돌은 중단하고 기존 자료를 보존합니다. 다른 실행의 잠금은 지우지 않습니다. 이번 최초 수집 원문은 `output/external-finance-20261118`에, 업무 예시를 제31조로 고친 최종 묶음은 `output/external-finance-20261118-v2`에 있습니다. 두 폴더의 수집 본문은 같습니다.

회귀 테스트는 실제 API 없이 현행·예정 분리, 필수 하위법령 누락, 소관·명칭 검증, KIC 분리, 기존 자료 폴더 보호를 확인합니다. 등록된 `offline` 테스트 묶음에도 포함됩니다.

## 공개 자료 묶음과 다음 갱신

기존 공개 자료에 이 범위를 처음 추가할 때는 검증된 공개 자료 폴더를 기준으로 아래 명령을 실행합니다. 목적지는 새 폴더입니다.

```powershell
uv run --frozen python -m scripts.build_external_finance_site --base <기존-공개-자료-폴더> --bundle output/external-finance-20261118-v2/validated-bundle.json --kic output/external-finance-20261118-v2/kic-source.json --destination output/external-finance-preview
uv run --frozen python -m scripts.verify_external_finance_site --base <기존-공개-자료-폴더> --site output/external-finance-preview
node scripts/verify_external_finance_guide.mjs --site output/external-finance-preview
```

전 분야를 처음부터 빌드하는 경우에는 검증한 수출·해외사업 금융 묶음을 소스 루트의 `output/export_finance-universe/bundle.json`으로 준비하고, 해당 현행 KIC 두 문서를 외환 수집 묶음에 포함합니다. 두 빌드 경로에서 같은 분야 간 연결 생성기를 사용합니다.

공개 배포 작업은 [고정된 자료 묶음](../static-web-release.json)의 체크섬과 화면 파일을 저장소 코드와 대조합니다. 새 자료와 화면을 함께 묶어 고정 정보를 갱신해야 배포할 수 있습니다. 새 분야가 포함된 묶음은 길잡이의 근거 조문과 판본도 검증합니다. 공개 이후에는 전 분야 판본 점검기가 목록에 있는 새 법령을 함께 점검합니다.

## 수집과 연결의 한계

- 네 근거법 계열을 선정해 수집했습니다. 공급망 관련 모든 제도, 정책금융 전체, 기관 내규와 모든 행정규칙을 포괄하지 않습니다.
- 상품별 지원요건·심사기준·보험약관, 개발협력 사업 협정, 위탁계약서와 실제 거래조건은 수집하지 않았습니다.
- 본칙의 명시적 인용을 분석합니다. 별표·서식 본문, 부칙의 경과조치 전체와 첨부파일 내부 인용을 이번 작업에서 검증한 것은 아닙니다.
- 인용에는 적용, 제외, 간주, 위탁, 정의 차용 등이 섞입니다. 연결선 하나로 해당 법률 전체의 적용이나 개인 거래의 적법성을 단정하지 않습니다. 특히 한국투자공사법 제38조의 외국환 관련 간주와 자본시장법 적용 제외·예외는 본문을 함께 읽어야 합니다.
- 수집된 양쪽 본문이 있어야 역인용과 실제 내용을 함께 확인할 수 있습니다. 미수집 법령과 의미상 유사한 규정까지 모두 찾았다는 뜻은 아닙니다.
- 이번 수집·검증은 공개 배포 완료를 뜻하지 않습니다. 공개 자료 반영 전에는 별도의 통합·화면 검증과 배포 절차가 필요합니다.
