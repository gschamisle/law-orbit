## 수동 실행

`C:\Users\gscha\codexproject\FscLawGalaxy-Stage2`에서 다음 명령을 실행한다.

```powershell
.\.venv\Scripts\python.exe -m scripts.update_law_galaxies --mode auto
```

목록만 비교하려면 `--check-only`, 전체 수집을 즉시 실행하려면 `--mode full`을 사용한다. 기존 환경변수·로컬 설정에서 `LAW_API_KEY` 또는 `LAW_OC`를 읽는다. 인증값은 명령 인수나 로그에 넣지 않는다.

## 저장과 검증

- 세법: `output/tax-universe/bundle.json`
- 금융위: `output/fsc-universe/bundle.json`
- 최근 결과: `output/law-updates/latest.json`
- 실행 기록: `output/law-updates/runs/`
- 교체 전 자료: 각 은하의 `history/<실행 ID>/bundle.json`
- 수집 중 자료: 각 은하의 `staging/<실행 ID>/`

세법은 기존 수집 법령군을 유지하고 금융위는 금융위 소관 법령·행정규칙 및 지정된 금감원 업권별 시행세칙을 별도로 수집한다. 원문·그래프 범위 일치, 종전 자료 누락 여부, 시행일 역행·미래 판본, 조문 분석 유지 여부, 인용 근거의 원문 일치를 검사한 뒤 한 파일을 원자적으로 교체한다. 어느 한 은하의 실패가 다른 은하의 정상 갱신을 막지는 않는다. 실패한 은하는 기존 자료를 유지한다.

기존 `data/`의 세법 원본과 개정안 검토용 자료는 덮어쓰지 않는다. 앱의 세법 은하·조문 탐색은 별도 갱신 파일을 우선 읽는다. 개정안 검토용 다른 자료까지 자동 갱신했다는 의미는 아니다. 금융위의 본문만 수집되고 조문 분석되지 않은 자료는 계속 미분석 상태로 남는다.

목록 누락·법령명 변경·분석 실패는 자동으로 범위를 축소하지 않고 확인이 필요한 오류로 처리한다. 동시 실행은 잠금으로 막는다. 강제 종료 후 잠금이 남았다면 실제 실행 중인 프로세스가 없는지 확인한 뒤 담당자가 처리해야 한다.
