## 수집·검증 방식

1. 패치 적용 후 기존 오프라인 31개 모듈 실행. 별표 제목의 조문 연결 누락 1건을 발견하여 수정하고 해당 검사를 통과했다.
2. 법령 목록 → 행정규칙 목록 → 본문 수집 → 그래프 생성 순서로 진행했다.
3. 법령과 행정규칙의 현행 지정 값이 서로 다른 점을 [법령 목록 가이드](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsEfYdListGuide)와 [행정규칙 목록 가이드](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=admrulListGuide)에서 확인했다.
4. 실제 응답의 페이지 번호·총건수·중복 식별자·기관·공포일/시행일을 검사했다. 법령 본문은 MST와 시행일, 행정규칙은 판본 일련번호를 지정했다.
5. 공동 소관 자료는 목록에 전체 기관, 본문에 대표 기관 또는 복수 기관이 표시되는 차이를 반영했다. 본문 기관이 목록의 기관 집합에 포함되는지 확인하며 기관 검증을 유지한다.
6. 성공한 본문은 무결성 해시를 가진 전용 캐시에 보관한다. 실패 시 이전 완료 번들을 바꾸지 않고 원인과 성공 캐시를 남겨 재개할 수 있게 했다.
7. 현재 목록을 다시 조회하고 검증된 같은 날·같은 판본의 캐시를 재사용하여 정식 수집 명령의 끝까지 실행했다.

기존 프로젝트 설정, 현재 환경변수, Windows 사용자 환경변수에서 인증값을 확인했다.
기존 인증값을 재사용했으며 인증값을 대화·터미널·로그·Git에 기록하지 않았다.
실행 도구는 현재 환경 → 이 작업 폴더의 `.env` → Windows 사용자 환경 순으로 `LAW_API_KEY` 또는 `LAW_OC`를 찾는다.
값이 없을 때만 이 폴더 `.env`의 `LAW_API_KEY=` 항목을 안내한다.

`--bootstrap`과 `--with-tax-corpus`는 실행하지 않았다. 독립 수집 CLI에서는 두 옵션을 제공하지 않는다.

## 데이터와 상태

금융위 산출물은 모두 `output/fsc-universe`에 저장하며 Git에서 제외된다.

- `bundle.json`: UI가 읽는 검증된 본문·그래프·요약의 원자적 번들
- `inventory.json`: 공식 목록과 판본 식별자
- `source-checkpoint.json`: 수집 완료 본문; 그래프만 다시 생성할 때 사용
- `body-cache/`: 판본·수집일·해시를 확인하는 재개용 캐시
- `report.json`: 실제 수집·인용 건수
- `verification.json`: 원본 보호, 인용 원문 위치, 데이터 분리 검증 결과
- `offline-tests.log`, `collection-tests.log`, `focus-tests.log`, `isolation-tests.log`: 테스트 기록
- `verified-collection.log`: 정식 수집 실행 기록

초기 점검용 `response-checks/`에는 인증 부분을 제거한 공개 XML만 저장했다.
`collection-failures.json`은 최초 발견해 해결한 공동 소관 3건의 진단 기록이다. 현재 완료 번들의 실패 건수를 뜻하지 않는다.

세법은 `core.law_universe`의 기존 경로, 금융법은 `core.fsc_universe.BUNDLE`만 사용한다.
금융위 번들이 없으면 **금융위 데이터 미수집**을 표시한다.
데이터 범위가 잘못되면 오류로 표시하며 세법·샘플 데이터로 대체하지 않는다.

화면 키는 세법의 `lm_*`와 금융의 `fsc_*`로 나뉜다. 금융용 캐시 함수에는 금융 번들 경로와 파일 변경 정보가 들어간다.
선택 법령·입력 조문·필터·조회 선택 상태가 서로 섞이지 않는다.
두 3D 화면은 각각 별도 iframe에서 실행되어 선택 노드도 공유하지 않는다.

## 외부 법령 및 감독규정

기본 지도에는 수집된 금융위 법령만 표시한다. 세법 은하의 노드와 연결선을 불러오지 않는다.
미수집 외부 대상의 인용은 별도 목록에 출처 조항·호·목, 인용 원문, 문맥, 공식 링크, 미수집 상태로 보존한다.
외부 본문이나 역인용을 검토했다고 표시하지 않는다.
수집된 법령의 근거 링크는 수집 판본을 가리킨다.

행정규칙은 본문 조회 메뉴에서 확인할 수 있으며 **본문 수집 / 연결 미분석**으로 표시한다.
행정규칙 본문을 일반 법령 조문 파서에 넣지 않으며 기본 지도에도 넣지 않는다.

## 약칭과 화면

- 법제처 응답의 `법령약칭명`을 보존하고 법령 선택·전체 은하·조문 강조 노드에 사용한다.
- 예: 자본시장법, 외부감사법, 금융실명법, 개인채무자보호법, 테러자금금지법.
- 시행령·시행규칙의 공식 약칭도 각각 구분한다.
- 공식 약칭이 없는 긴 규정 7건은 `core/fsc_labels.py`에 명시된 지도용 축약명을 사용한다. 공식 약칭으로 주장하지 않는다.
- 정식 명칭은 식별자·분석·원문·링크에 그대로 사용하고, 노드 선택 시 정식 명칭을 보여 준다.
- 금융 지도에서 라벨 겹침을 줄이고, 선택·마우스 오버 시 해당 이름을 우선 표시한다.
- 나눔명조를 번들에 포함한다. 실제 브라우저의 글꼴 로딩 상태 `loaded`를 확인했다.

## 재수집 및 테스트

다음 명령은 위 작업 폴더에서 실행한다.

```powershell
# 목록만: 법령 → 행정규칙 순서
& '.\.venv\Scripts\python.exe' -m scripts.collect_fsc_universe --inventory-only

# 당일 목록 재사용, 본문 수집 후 그래프 생성
& '.\.venv\Scripts\python.exe' -m scripts.collect_fsc_universe --reuse-inventory

# 금융위 수집 완료 본문에서 그래프만 다시 생성
& '.\.venv\Scripts\python.exe' -m scripts.collect_fsc_universe --build-only

# 전체 회귀 테스트
& '.\.venv\Scripts\python.exe' scripts/run_offline_tests.py
```

인증값 없이 이미 수집된 금융법은하를 탐색할 수 있다. 새 API 수집에는 인증이 필요하다.
자동 갱신 일정은 설정하지 않았다.
