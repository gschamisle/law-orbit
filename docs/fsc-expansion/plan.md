# 금융위 법령 확장 계획 — 1차 초안

기준일: 2026-09-16  
기준 코드: `codex/precise-citation-impact` @ `329d7ec5e055f1c81821aa3d89db9553cc119a3b`

## 1. 출발점

이번 기준 브랜치에서 세법 은하는 이미 **시행일 기준 법령 ID로 105개 법령을 수집하고, 조문·항·호·목의 증거 위치를 보존한 직접/역인용 그래프**로 발전했다. 따라서 금융위 확장은 별도 프로그램을 복제하기보다 다음 공통 자산을 재사용하는 것이 안전하다.

- `scripts/collect_law_universe.py`: `eflaw` 시행일 기준 수집, 법령 ID/MST/시행일/원문 해시 보존
- `core/universe_builder.py`: 인용·준용·법령전체 참조·별표 참조를 증거 원문과 함께 간선화
- `core/citation_scope.py`, `core/galaxy_focus.py`: 세부 조문 범위 판정과 순방향/역방향 영향 탐색
- `data/law-galaxy-sources.json` / `data/law-galaxy-graph.json`: 공개 원문과 파생 그래프 분리

다만 현재 빌더는 `category == "tax"`를 중심축으로 외부법↔외부법 간선을 의도적으로 버린다. 금융위 확장의 핵심은 이 구조를 **도메인별 focus category**로 일반화하되, 기존 tax 동작을 기본값으로 그대로 보존하는 것이다.

## 2. 제1원칙

금융위 확장도 기존 프로젝트의 원칙을 그대로 따른다.

> 후보 탐지는 규칙·그래프·공식 식별자에 맡기고, LLM은 애매한 개정 필요성의 설명과 사람의 판단 보조에만 사용한다. 못 읽은 자료는 "영향 없음"으로 취급하지 않는다.

따라서 다음 상태를 결과에 명시한다.

- `verified`: 공식 원문과 ID/시행본까지 확인
- `seeded`: 공식 소관 목록에서 명칭은 확인했으나 ID/시행본 미해결
- `not-collected`: 해당 레이어를 아직 수집하지 않음
- `fetch-failed`: 수집을 시도했으나 실패
- `out-of-scope`: 선언한 탐색 범위 밖
- `review-required`: 구조적 연결은 있으나 함께 개정해야 하는지는 사람이 판단

## 3. 수집 범위

### A. 법률·대통령령·총리령

금융위원회 공식 「금융위 소관법규」 목록을 인벤토리 출발점으로 삼고, 실제 본문은 국가법령정보 공동활용 `eflaw` API에서 **정확한 법령명 → 법령 ID → 기준일 시행본** 순으로 해결한다. 2026-09-16 현재 금융위 화면은 117건을 12페이지로 제공하지만, 이번 초안의 코드에는 그 전체를 임의로 옮기지 않고 공식 화면에서 직접 확인한 핵심 법률명만 seed로 둔다.

법률명 뒤에 문자열로 `시행령`, `시행규칙`을 붙여 관계를 확정하지 않는다. 같은 명칭 계열이라도 실제 법령 ID와 소관·종류를 확인해 family를 만든다. 특히 금융위 목록에는 이름만 보면 행정규칙처럼 보이는 규범이 대통령령·총리령으로 존재할 수 있으므로 이름 접미사만으로 종류를 판단하지 않는다.

### B. 금융위 행정규칙

국가법령정보 공동활용의 행정규칙 API(`target=admrul`)를 별도 어댑터로 사용한다. 이 API는 `nw=1`이 현행, `nw=2`가 연혁이며, `org` 소관부처와 `knd`(훈령/예규/고시/공고/지침/기타)를 제공한다. 법령 시행일 목록의 `nw` 의미와 같다고 가정하지 않는다.

금융위 홈페이지의 「규정/고시/공고/훈령」 게시판은 현행 규범 본문뿐 아니라 개정 고시, 변경등록 공고, 개별 처분성 공고 등이 섞일 수 있으므로 **게시물 목록 자체를 규범 corpus로 사용하지 않는다**. 법제처 행정규칙 본문 또는 다른 공식 원문과 매칭된 항목만 그래프에 넣는다.

### C. 금융감독원 시행세칙 등

발령 주체가 금융위원회가 아닌 금융감독원인 규정은 별도 issuer로 보존한다. 금융위 행정규칙과 합치거나, 법률명에서 자동 생성하지 않는다. 1차 구현에서는 수집 상태를 `not-collected`로 명시하고, 공식 FSS 원문 출처와 버전 식별 방법이 정해진 뒤 추가한다.

### D. 타부처 법령 역인용

금융법을 바깥으로 확장할 때 가장 중요한 것은 "금융법이 무엇을 인용하나"뿐 아니라 **다른 부처 법령이 금융법을 무엇으로 인용하나**이다. 세법 은하에 이미 들어 있는 자본시장법·은행법·보험업법·여전법·외부감사법은 첫 bridge corpus로 재사용한다. 이후 외부 corpus는 다음 순서로 넓힌다.

1. 기존 세법 은하 105개 법령에서 금융법 역인용
2. 금융위 소관법규 전체 법령군 내부
3. 법제처 전체 현행 법령에서 금융위 핵심법 직접 인용 후보
4. 확인된 후보의 소관부처별 정밀 수집

전체 국내 법령을 아직 읽지 않은 상태에서 "역인용 없음"이라고 표시하지 않는다.

## 4. 그래프 모델

법령 노드는 최소 다음 식별자를 가진다.

- `canonical_name`
- `law_id` (법령/행정규칙 종류에 맞는 공식 ID)
- `mst` 또는 해당 버전 식별자
- `issuer` / `ministry`
- `norm_type` (법률·대통령령·총리령·고시·훈령·FSS rule 등)
- `effective_from`
- `promulgated_at`
- `content_hash`
- `collection_state`

간선은 기존 증거 구조를 유지하면서 `source_ref`, `target_ref`, `cite_raw`, `context`, `source_effective`, `target_effective`, `evidence_id`를 보존한다. 관계 유형은 최소 다음을 구분한다.

- `direct` / `junyo`: 특정 조문 인용·준용
- `law_reference`: 조문을 특정하지 않은 법률·정의 참조
- `annex_reference`: 별표·별지 연결
- `delegation`: 상위법 위임과 하위 규범의 집행 관계 — 공식 근거를 확인한 경우만
- `parallel_review`: 업권 간 유사 규율 — 자동 개정 의무가 아닌 검토 후보

"역인용"은 별도 간선을 중복 저장하기보다 동일 간선을 반대로 조회한다.

## 5. 개정 영향 판정

사용자가 `자본시장법 제X조` 개정안을 넣었을 때 화면은 연결 후보와 개정 필요성을 분리해야 한다.

1. **구조적 후보 탐지**: 직접 인용, 준용, 정의 참조, 위임, 별표, 조문 이동/삭제 후 잔존 인용
2. **개정안 대조**: 부칙의 타법개정 또는 함께 제출된 개정안에 이미 반영했는지 확인
3. **시점 대조**: 기준일 현행본, 공포 후 미시행본, 사용자 개정안을 분리
4. **판단 큐**: `반영`, `미반영 의심`, `조치불요`, `사람검토`, `미점검`
5. **근거 표시**: 각 후보마다 원문 인용문, 공식 원문 링크, 사용한 시행본을 표시

부칙의 경과조치·종전 규정 적용 때문에 옛 조문명이 남는 경우를 단순 오류로 확정하지 않는다.

## 6. 구축 우선순위

우선순위는 실제 중심성을 계산한 순위가 아니라 **기능 검증 순서**다. 전체 그래프가 만들어지기 전에는 인용 건수나 중심성을 계산한 것처럼 표현하지 않는다.

1. `자본시장과 금융투자업에 관한 법률` — 대형 법률, 시행령·규칙·감독규정 연결 검증
2. `금융실명거래 및 비밀보장에 관한 법률` — 세법과의 bridge 및 특수한 부칙 관련 규칙 검증
3. `금융소비자 보호에 관한 법률` — 여러 업권법에 걸친 적용범위 검증
4. `금융회사의 지배구조에 관한 법률` — 금융회사 정의를 통한 다수 업권법 참조 검증
5. `신용정보의 이용 및 보호에 관한 법률` — 정보·업권 간 법령 관계 검증

그 다음 은행/보험/여전/저축은행/예금자보호/디지털금융 순으로 넓힌다.

## 7. 구현 단계

### Phase 0 — 이번 브랜치

- `core/law_domains.py`에 도메인 registry 계약 추가
- 기존 tax가 기본값임을 회귀 테스트로 고정
- 금융위 공식 목록에서 직접 확인한 핵심 법률명을 `verified-name-only` seed로 추가
- 행정규칙/FSS rule/외부 역인용을 별도 collection layer로 선언
- 법령 ID·MST·시행일은 아직 채우지 않고 공식 API 해결 전 상태를 명시

### Phase 1 — 전체 법령 인벤토리

- 금융위 117개 소관법규를 기준일과 함께 전수 수집
- `eflaw`에서 법령 ID, MST, 종류, 시행일, 공포일 확인
- 법률 family를 ID 기반으로 구성하고 불일치/중복/미시행본을 감사 로그에 기록

### Phase 2 — 행정규칙

- `admrul` 소관부처 필터로 현행 규칙 전수 후보화
- FSC 게시판은 cross-check만 수행
- 현행/연혁 의미를 API 어댑터에서 명시적으로 변환
- 법률↔감독규정 관계는 본문의 위임/인용 또는 검증된 매핑 근거가 있을 때만 연결

### Phase 3 — 빌더 일반화

`core/universe_builder.py`의 `category == "tax"` 조건을 `focus_category` 또는 `domain_key`로 일반화한다. 기본값은 `tax`로 두어 현재 105개 세법 은하의 간선 수·검증 사례가 그대로 유지되어야 한다. 금융위 그래프는 `fsc`가 source 또는 target인 간선을 중심으로 만들고, 외부↔외부 일반망은 계속 제외할 수 있다.

### Phase 4 — 개정안 누락 탐지 통합

세법의 조문 이동·재사용·병행개정 탐지 흐름에 금융위 도메인을 붙여, "연결됨"과 "이번 개정안에 미반영"을 분리해 보여준다. AI는 후보 삭제 권한을 갖지 않는다.

## 8. 완료 기준

- 수집 대상/성공/실패/미점검 건수가 결과에 항상 남는다.
- 모든 그래프 간선이 증거 원문 또는 공식 relation 근거로 역추적된다.
- 특정 시점의 법령 ID와 시행본을 재현할 수 있다.
- 행정규칙/FSS 규정이 이름 추정만으로 법률과 연결되지 않는다.
- 기존 세법 105개 corpus와 회귀 테스트가 깨지지 않는다.
- 알려진 금융위 인용조문 누락 사례를 golden case로 추가하고 false negative를 우선 관리한다.
