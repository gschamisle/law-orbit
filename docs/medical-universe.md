# 보건·의료 — 수집 범위와 검증

2026-10-12, 감염병·응급의료를 추가했다. 분야 ID와 저장 경로는 `medical`로 유지한다. 임상·급여 기준의 해석이나 적합성 판정이 아닌, **조문과 명시적 인용 근거를 함께 읽는 도구**다.

## 실제 수집 범위

| 세부 분야 | 선정 법령·규정 | 문서 수 |
|---|---|---:|

| 지역·공공보건 | 보건의료기본법·시행령, 지역보건법·공공보건의료법·국민건강증진법 및 각각의 시행령·시행규칙 | 11 |

- 법령 31개·선정 행정규칙 5개, **36개 문서·1,974개 조문 레코드**다. 조문 레코드에는 삭제 조문도 포함하며 별표 칸·문단은 제외한다.
- 내부 인용 근거 5,173건, 미수집 외부 법령 인용 근거 1,295건, 미해결 문구 402건이다. 근거 위치의 수이며 서로 다른 조문 수나 개정 의무 건수가 아니다. 문맥 확인 후보도 포함한다.
- 35개 문서에서 조문을 분석한다. **감염병 신고를 위한 진단기준 고시는 문단·표 형식**이므로 본문 열람과 공식 원문 링크를 제공하며 조문 연결은 미분석으로 표시한다. 임의의 조문 번호를 만들지 않는다.
- 별표·서식 메타데이터 483개 중 본문 검증 4개를 유지한다. 나머지 479개는 공식 파일로 직접 확인한다.

법령 제목과 소관 기관을 함께 확인한 선정 목록이다. 보건복지부 전체·질병관리청 전체 규정을 포괄하지 않는다. 감염병 법령군과 선정 감염병 고시는 질병관리청 소관 및 보건복지부 공동 소관을 허용하며, 다른 법령군에 이 예외를 확대하지 않는다. 본문 핵심어로 부여한 복수 분류는 탐색 보조이며 법적 적용범위가 아니다.

## 새로 확인한 연결

- 감염병법 제36조 → 의료법 제3조: 감염병관리기관의 지정 근거.
- 감염병 시행규칙 제31조 → 감염병법 제36조·제39조, 의료법 제34조, **별표 4의2**: 관리시설 설치 기준.
- 공공보건의료법 시행규칙 제2조의2 → 감염병법 제8조의2·제36조: 감염병전문병원과 관리기관의 연결.
- 응급의료법 제31조 → 의료법 제3조의2: 지역응급의료기관의 지정 근거.
- 응급의료 시행규칙 제18조 → 응급의료법 제31조, **별표 8·지정 서식**.
- 응급의료 시행규칙 제18조의4 → 응급의료법 제31조의4: 중증도 분류 근거.

기존 의료법 제43조와 의료인 정원표, 지역보건법 제11조, 국민건강보험법 제42조 등도 함께 제공한다. 법령 전체 참조를 특정 조문 인용으로 바꾸지 않는다.

## 인용 처리 보완

**생략된 법령명:** `「감염병…법률」 제8조의2에 따른 감염병전문병원 및 제36조…`의 뒤 인용은 앞의 명시된 법령을 이어받는다. 같은 문장 안의 제한된 연결 표현만 지원하고, 문장·문단이 바뀌거나 새로운 법령·자기 법령이 명시되면 중단한다. 원문 위치를 보존하며 상대 참조는 문맥 확인 후보로 표시한다.

**같은 법·동법:** 앞에서 확인한 법률의 `동법 시행규칙`을 해당 하위법령으로 찾는다. 명시된 선행 법령을 확인할 수 없으면 자기 법령으로 추정하지 않고 미해결로 남긴다.

**옛 조문 번호:** 중증도 분류 고시의 제1조는 아직 응급의료 시행규칙의 옛 제18조의3을 인용한다. 수집 판본의 해당 번호는 재지정 절차이고 중증도 분류는 제18조의4로 이동했다. 원문 번호를 자동 교정하지 않고 **조문 이동·판본 확인 필요**를 근거 목록과 연결 조문 본문에 표시한다. 이동일이 없는 API 이력도 확인 후보로 남기며 이동 후보가 법적 동일성을 확정하지는 않는다.

## 판본과 별표 보존

신규 수집에서 기존 의료법(20261002), 국민건강보험법(20261008), 국민건강보험법 시행령(20261001)의 새 시행 판본이 확인됐다. 기존 공개 자료와 새 공식 수집본의 시행일·조문 내용 해시·별표 메타데이터 해시를 대조한 명시적 변경 목록만 허용한다.

**의료법 시행규칙 별표 3·4·5, 진료지원업무 수행행위 목록 고시의 번호 없는 별표** 4개는 본문·파일 해시와 칸·문단 위치를 그대로 보존했다. 소유 문서의 XML 구조·본문·순서가 바뀌면 이전 분석을 붙이지 않는다. 나머지 17개 분야 및 기존 분야 간 연결은 메타데이터와 연결된 자료 바이트를 대조해 보존한다.

## 실행과 검증

수집·분석은 활성 자료를 덮어쓰지 않는 새 폴더에서 수행한다. 인증값과 수집 캐시는 Git에 넣지 않는다. 검증이 끝난 묶음만 로컬 앱과 공개판에 반영한다.

```powershell
python -m scripts.collect_healthcare_expansion --stage inventory --destination output/healthcare-phase2-20261012 --date 20261012
python -m scripts.collect_healthcare_expansion --stage bodies --destination output/healthcare-phase2-20261012 --date 20261012
python -m scripts.collect_healthcare_expansion --stage build --destination output/healthcare-phase2-20261012 --date 20261012
python -m scripts.test_healthcare_phase2
python -m scripts.test_healthcare_site
python -m scripts.test_medical
```

매번 새 출력 폴더를 사용한다. 정적 공개 빌더의 `--edition-updates`는 검토한 구판·신판의 정확한 시행일과 조문·별표 해시를 담은 JSON을 받는다. 확인되지 않은 변경과 분석된 별표의 변경은 거절한다. [이번 확장 검증 기록](qa/healthcare-phase2-20261012.md)
